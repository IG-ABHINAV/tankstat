# Frontend: UI structure, grids, bundle size, charts and libraries

- **UI structure:** `react-router` pages in `src/frontend/tankstat-react/src/pages` (vehicle page tabs in `pages/vehicle`), shell (top bar, docked/overlay navigation, health footer: always the web app's version, `appVersion.ts` = `__APP_VERSION__` defined by `vite.config.ts` from the build's `VERSION` (CI's frontend job, the Dockerfile's frontend stage, checked by `docker-smoke.sh`), then the API's status and version while the server answers, else the connectivity message) in `src/frontend/tankstat-react/src/shell`; shared bits: `forms/` (`Form`: native constraint validation with `noValidate`, on submit every Field refreshes its custom validity, `checkValidity()` shows the messages and the first invalid control takes the focus; `refusal` (the form's last submit error) said at the field it is about (`forms/refusals.ts` `FIELD_OF_KEY`: a server's `*Required` key to the form's field name), which takes the focus, while an `ErrorMessage` of the same error inside the form says nothing, so every required value is said at its field, the form's own check or the server's; `Field`: label above, hint, `extra` and error messages linked by `aria-describedby` (its own check first, then `refusal`, the server's word on the value sent); `FieldInput`, `FieldDate` (MUI X picker, lazy `DatePickerImpl`, hidden ISO input, `disableFuture`), `FieldAutocomplete`, `CurrencyInput` (ISO codes with `Intl` names), `PasswordInput` for every password, passphrase or secret (#120: a real `type="password"` input with the caller's `autoComplete`, a Show button of its own per field (`aria-pressed`, `aria-controls`, `showLabel` saying what it shows) that is never on at first and hides again after `REVEAL_IDLE_MS` (30 s) without a keystroke, on leaving the field and its button, on its form's submit (also one the checks stop) and on unmount; the button's `mousedown` keeps the focus in the input; Edge's own reveal hidden; a Caps Lock note in the field's description inside a `role="status"`), `NewPasswordFields` for a new password and its repetition `<name>Repeat` (each a `PasswordInput`, `autocomplete="new-password"`; the new one says the minimum before typing (`forms.password.requirements`, from the public `PasswordRequirements` query, `keep` offline, `PASSWORD_FLOOR` 10 without an answer) and a shorter one is its own `invalid` (`errors.password.tooShort`), as is a password longer than the query's `maxLength` (`errors.password.tooLong`; never a passphrase's, which has no ceiling, and no native `maxlength`, which would cut a paste short without a word); once something is typed a strength meter in its `extra` (`FieldMessage`, the words in the description, not a live region; a `LinearProgress` bar beside them, `aria-hidden`, coloured by the score as well as worded): `forms/passwordStrength.ts`, pure, no dependency (zxcvbn-ts was measured too big and has no Hungarian), 0..4 from what each character costs to guess (a letter in a word 2.5 bits, accented ones too (Unicode classes), a first capital 1, a digit 3.3, a symbol 4, a pattern's 0.5, a common password (leet undone on both sides, `trustno1`) or a piece of the person's own name or address (all but the address's top-level domain: `com` is everybody's) 6 bits as a whole, compared character by character after the same folding on both sides (lowercase, accents stripped: `jelszó` is `jelszo`), so a character outside the BMP never shifts what is marked; thresholds 26/36/48/60; only the first 128 characters are looked at, `MAX_ANALYSED`, since the repeated pieces cost the cube of the length and a paste is analysed on every keystroke), under the minimum always 0 (counted in UTF-16 units, as the field and the server count), the reasons as keys `forms.password.strength.reasons.*` (two shown, none from 3 on), advisory only (never stops a form); `personal` (FieldDef too): the change form the signed-in user's, the administrator's Set password the user's, none on the reset page and the setup; `minLength`, `hint` and `tooShort` for a passphrase (the key set: `Backups:PassphraseMinLength`, the requirements query skipped; with `required={false}` only spaces counts as empty: no check, no meter); a different repetition is the field's own `invalid`, `errors.password.mismatch`, so the form stops the submit and focuses it), `FieldForm` for plain text forms, `type: 'password'` rendering a `PasswordInput`, `type: 'newPassword'` the pair with `repeatLabel`; `PasswordForms.tsx`: `ChangePasswordForm` (`required` for the gate: no heading of its own; once the change is saved the cached `Session` loses the flag (`update`), so the pages come back at once, then `Session` is asked again past the device (`offline: 'bypass'`, never awaited: a failed answer must not make a saved password look refused, and the device's kept answer still has the flag); a toast) and `PasswordChangeRequiredView`, which `App.tsx` shows in place of every page, without the menu (`showMenu`), while `session.user.passwordChangeRequired`; the UI settings stay on meanwhile (`UiSettingsProvider` is enabled by `signedIn`, not by `showMenu`)), `dialogs/` (`DialogFrame` + `DialogButtons` + `DialogCancel`, `useDialogState` (own or controlled `open`), `DialogTrigger`, `onClosed` after the exit; `busy` blocks Escape and backdrop), `toast/` (`useToast`: `toast('Saved.')` after a save, `undoable(message, undo)` with Undo for 10 s after trashing a vehicle, refuelling or expense; the confirmation before trashing stays), `messages.tsx` (error/success alerts) and `components/` (`ConfirmDialog`, `ImagePicker`, `UserAvatar`, `VehiclePicture`, `OdometerField`, `LabeledSelect`/`InlineSelect` (an option may carry an `icon`, drawn in the list and the closed field), `LabeledSwitch`, `IconAction` (icon button + tooltip + aria-label from one label), `TabbedPanels` (a panel per tab, only the open one filled), `Segmented` (real radios in a pill; an option with an `icon` shows it instead of its words, which stay its name and tooltip; a `disabled` one stays in place, dimmed, its `reason` in the tooltip and in the input's description, since a disabled input takes no focus) and `SegmentedChecks` (the same pill of checkboxes for things that can be on together), `DefinitionList`, `SurfaceTable`). The sidebar is docked and open by default on desktop (`tankstat.nav.open` in localStorage is the device's copy, the account's value comes through `UiSettingsProvider`, see Settings), an overlay on phones (never remembered). Pictures: resize in the browser (`pictures/resizeImage.ts`), upload raw with `pictures/upload.ts`; `ImagePicker` sends at once; only a vehicle's picture (`keep`) can wait on the device (see A vehicle's picture offline), anything else keeps nothing for later, so it is off while the server is out of reach (`image.needsServer` as its description) and shows a lost connection as the calm `OfflineError` note. Look (`theme/`): dim dark sand/indigo palette copied once from Radix Colors (`scales.ts`), floating panels drawn by `glass(theme)` in `components.ts` (top bar, drawer, dialogs, menus, popovers, cards, `SurfaceTable`, the toasts; never a see-through background of their own) as the user chose (**Surfaces**: Glossy = translucent and blurred, the default; Transparent = translucent, no blur; Opaque = solid paper of the panel's own scheme): `glass` reads `--tk-glass-alpha` (0.7 dark, 0.85 light, merged into the shadow tokens' `:root, .dark`/`.light` rules) and `--tk-glass-filter`, and a class on `<html>` (`surface-transparent`/`surface-opaque`, `theme/surface.ts` `SURFACE_CLASS`; glossy has none) switches them (`SURFACE_TOKENS`, which also hold the home card figures' `--tk-scrim`/`--tk-scrim-filter`); `theme/surfaceStore.ts` (`setSurface`, `useSurface`) sets the class and the browser's copy (`tankstat.surface`), the account keeps `UiSettings.Surface` (`UiSettingsProvider.setSurface`); a toast is `glass` with its severity's `soft` tint over it, text in `text.primary`, the icon in `softText`, a hairline in the severity's colour and `shadows[9]`, and lets taps through to the page under it (`pointer-events: none` on the Snackbar's root, which a phone's screen width takes, `auto` on its button: it comes at the bottom over whatever control is there, the offline-ready one on its own time, #239; so the pointer pauses its timer only on Undo, the focus anywhere in it; its button runs its action once: a second tap or Enter while the message fades out does nothing (#243), never by turning the pointer off or disabling the button, which would not stop the key), soft shadows (`--tk-shadow-n` variables), pill controls, soft/ghost button and chip variants, **solid fills chosen for their text** (#235: every tone has `solid`/`solidHover`, at least 4.5:1 with its `contrastText` at rest and under the pointer, `scales.ts` `SOLID` for the white-text hues since Radix's step 9 is no contrast step (white on red, green and blue 9 is under 4.5:1, indigo's step 10 too in the dark scheme); a contained button (its `--variant-containedBg`), a badge and a solid chip are drawn on them, and `dark`, MUI's own hover, is `solidHover`; `main` stays step 9 for rings, checked controls and borders; never put white text on a Radix step directly; `tests/ui/Theme.unit.test.tsx` checks the table), system fonts; light and dark schemes as CSS variables (class on `<html>`, `ThemeProvider` with `modeStorageKey`). **Colour mode** (Light/Dark/System, default Dark): `shell/AppearanceMenu.tsx` next to the language menu (one menu, two groups: colour mode and surfaces; `RadioMenu` `groups`: a separator between them, a heading only seen, items named "<group>: <choice>" except a language's own name, which carries its `lang` and says itself, all the menu's own children), MUI's `useColorScheme`, the browser keeps it under `tankstat.colorMode`, the account under `UiSettings.ColorMode` (`UiSettingsProvider.setColorMode`; see Settings); `theme/initScheme.ts` is put into `index.html` by a Vite plugin (`vite.config.ts`) and sets the class, the colour scheme, `theme-color` and the surface class before the first paint (it must stay free of imports other than `colorMode.ts`, `scales.ts` and `surface.ts`, which import nothing and touch no page, since Vite loads them in Node; the store is `surfaceStore.ts`). Vehicle cards and the banner always have white text on a dark scrim, so they carry the `dark` class. Dialogs are uncontrolled where possible: `DialogTrigger` clones the caller's button, no open-state in the page; pass `open`/`onOpenChange` only when something else opens it (a menu, the floating add button, a home card's Done button). Tests render with `renderWithApollo(ui, route)` (MemoryRouter) and the in-memory `fakeVehicleBackend` from `src/frontend/tankstat-react/tests/support/mocks.tsx`; the footer's status badge also has `role="status"`, so query status messages by text.

- **Grids:** sorting/paging/column selection are server-side only (`VehicleQuery`/`RefuelingQuery`: orderBy/direction/skip/take; count queries for paging). `grid/ServerGrid` runs on MUI X's Data Grid in server mode (`sortingMode`/`paginationMode="server"`; the first visible column is the `rowHeader`; `autoHeight` + `disableVirtualization` + auto row height, so it holds at most 100 rows; no column menu, filter or resizing; the footer's texts come from our i18n, `huHU` for the rest). A row being trashed fades (`useLeavingRows`, `.tk-leaving`) while the server removes it. `ServerGrid` + `useGridSettings` (own state types, no table library) (localStorage `tankstat.grid.<id>` is the device's copy, the account's through `UiSettingsProvider` when one is mounted; `merge` validates against current columns) are generic; add a column by adding a `GridColumn` (and the `@include` variable); `defaultHidden: true` hides a column on every screen until the user shows it (a saved choice wins), while `mobile: false` hides it on phones only. Repositories always end the order with the id so pages are stable. A field resolved per row of a list (a log's `canEdit`/`canDelete`, `createdBy`, `vehicle`) goes through a batch data loader (`Api/GraphQL/LogRowLoaders.cs`, `AccessService.LogLevelsAsync`), never a query of its own: HotChocolate resolves rows in parallel, so a page of 100 rows asked one by one opened hundreds of connections at once and failed on PostgreSQL (`LogListQueriesTests` counts the contexts a page uses). Queries use `cache-and-network` so every visit refetches.

- **Touch targets:** on a touch screen (`COARSE`, `(pointer: coarse)` in `theme/components.ts`) every control is at least 44 px; the theme gives it to buttons, icon buttons, menu items, fields, checkboxes and radios. A text link counts too unless it is inline in a sentence (WCAG 2.5.8's exception; its parent has text of its own, as the Overview's "Go to Server settings"): a link on its own (a value in a `DefinitionList`, a name in a grid, a "Change the settings" line under a panel, a `Link component="button"`) spreads `standaloneLink` last in its `sx` (inline-flex, 44 px tall on a coarse pointer only; after the link's own `minHeight`, which would win otherwise). A link that flows after inline content (a notification behind its "New" chip) takes vertical padding instead (`NotificationItem`), which moves nothing, as long as no other target is within 44 px. The top bar's name keeps its block for the ellipsis and gets a 44 px line height. A stretched link (an absolutely positioned `::after` over its container, the home card's title) counts by its container. jsdom lays nothing out: sizes are measured in a real browser.
- **Bundle size:** every page in `App.tsx` is `React.lazy` (its own chunk), the dashboard and the two log tabs (the data grid) are lazy inside the vehicle page, sparklines through `LazySparkline` and the schedule dials through `LazyGauges`, the date picker inside `FieldDate`, so MUI X Charts (~145 kB), the Data Grid (~425 kB) and the pickers (~170 kB) only load when shown (the service worker precaches those chunks in the background after the first visit, see PWA); the entry chunk is the shell, MUI core, Apollo, i18n and the offline link (~470 kB, 149 kB gzipped; Emotion injects the styles, so the build has no stylesheet). Keep new pages lazy, and do not import `dashboard/*` (except `chartFormat.ts`) or `@mui/x-*` from eagerly loaded code. In tests lazy content appears asynchronously: use `findBy*`.
- **Charts:** MUI X Charts, always inside `ChartView` (bars, lines, areas, donuts; the picture is `aria-hidden`, `disableKeyboardNavigation`, `skipAnimation` under reduced motion; the same data is a table, `ChartTable` over `seriesText.ts`'s `useSeriesText` (the words the picture and the table share), opened in a dialog from the button in the card's header, `ChartTableDialog` (#228): keep it for accessibility, tests read the table because jsdom cannot lay out SVG); the picture is 240 px tall (the builder's preview), and in a dashboard tile (`ChartCard` `fill`, handed on to `ChartView`) as tall as the card leaves it (#227): no height reaches MUI X (its `ChartsWrapper` then takes `height: 100%` and the surface its box), the card's body, the `figure`, the picture and its `aria-hidden` box are flex columns, the picture from a basis of 0 (its size never feeds back into its room) and at least `MIN_PICTURE` (120 px), so the legend MUI X puts above the surface and the notes under it are counted by the browser and the body scrolls only once the table is opened; a tile's donuts (one per currency) share one row, never wrapped; a loading tile's skeleton takes the same room; series colours are `SERIES_COLORS` (`theme/scales.ts`). A bar chart is composed from MUI X's parts as its `BarChart` is (`ChartsDataProvider` > `ChartsWrapper` with `ChartsLegend`, `ChartsSurface` with `ChartsGrid`, `BarPlot` (the `PlacedBar` slot) and `LinePlot` in the clip path, `ChartsAxis`, then `ChartsTooltip` by axis in the page), so a trend or a year earlier (a series whose `role` is not `VALUE`) is a line over the bars on the same axes; a chart with no bar series at all (neither the first measure nor a second one) stays `LineChart` with those lines added (never an area, never stacked), any bar makes it composed (with `AreaPlot`, `LinePlot`, `MarkPlot` for a measure drawn otherwise). A second measure is drawn as its `secondKind`, never stacked (`barPlaces` stacks only the first measure's bars); every series is written in its own `unit` (`show`; a trend line at 0 is a 0, only a value or a year earlier at 0 is a dash), the first measure is the recipe's metric (`ChartView` hands it to `chartAxes` and `barPlaces`: the first measure may have no series in the range), and `chartAxes` keys an axis by unit (and currency for money): the first measure's on the left, a second measure's not already read by them on the right, each side shown only when it has one scale (`ownScales` says when not); the shown axis goes first in `yAxis`, since MUI's grid lines follow the first value axis; the margins give way to a shown axis on either side; `MarkPlot` sits outside the clip path, as in MUI's own `LineChart`, so a mark on the plot's edge is whole. Such a line takes its series' colour (a stack's total the next colours) and its scale, and is told apart by its stroke, not its colour (`OVERLAY_LOOK`: dashed trend, dotted fainter year earlier, through `sx` on `path[data-series=…]`, MUI's own attribute); the table lists it as a column of its own ("Total · HUF · moving average"), and notes under the chart (paragraphs, like the scales note) word a linear trend from its first value to its last and say why a line asked for is not there. A chart of costs (`unit` `CURRENCY`) gives every currency a y axis of its own (#159, `chartFormat.ts` `chartAxes`: `yAxisId` per series, `domainLimit: 'strict'`): with several, none is shown (`position: 'none'`), each from 0 (`min: 0`, so a line of prices that barely moves stays flat), no grid lines, and a note under the chart says so (`dashboard.ownScales`, a paragraph, not a `figcaption`: the title names the figure); with one, its axis is in that currency (`useFormat().compactMoney`, 64 px); a 0 in a currency is a dash in the tooltip and the table. Bars draw themselves (`dashboard/PlacedBar.tsx` as the `bar` slot, its layout from `barLayout.ts`'s context over `chartFormat.ts` `barPlaces`): a period's bars are only those of the groups it has (a currency when stacked, else a series), centred in the period's band (`useXScale`, MUI's public scale) at the width MUI gave the bar (`BAR_GAP_RATIO` between them), animated by MUI's `useAnimateBar`; the places are worked out once per chart (`barPlaces`, bar charts only); the stack's top gets a rounded cap over a square body there (the cap carries no MUI class), since MUI's `borderRadius` clips each bar where MUI put it; and since MUI still finds a bar under the pointer at its own place, the tooltip stays by axis (`trigger: 'axis'`) and no item highlight, item tooltip or item click is offered. The stack key is `stackOf` for MUI and `barPlaces` alike. Periods along the bottom are short on the axis, only in a chart by month or quarter (`shortPeriodLabels`; one key grammar, `parsePeriod`, shared with `periodLabel`): every `labelStep`-th period (`MONTH_LABEL_PX` per label over the figure's measured width, measured whenever the figure is rendered: `useWidth` takes it through a callback ref, since a chart that first said it had no data has no figure at mount and gets one when its data comes in (#237: without it the width stayed 0 and every period was named); `tickLabelInterval` names only those), the month alone, its year on a second line under the first one named and every named one that starts a year among them (so no year goes unnamed); `Q4 ’25`; a category as it is ("Uncategorised" for none, a "2025-03" category too); full in the tooltip (the x axis' `valueFormatter` by `context.location`, `dataKey: 'key'`, `height: 'auto'`); `LABEL_ROOM` keeps the margins MUI needs not to cut the first and last label (it allows twice a label's distance from the edge, a two-line label measured as one line). Check charts in a real browser (`src/frontend/tankstat-react/e2e/charts.e2e.ts`). The Recurring tab shows a dial per limit (`recurringProgress.ts`, pure, + `dashboard/ProgressGauges.tsx`: a combined schedule has two, the deciding one at full strength; a picture only, the state badge and due text say the same). Vehicle pictures are drawn by `CoverLayers` (the picture as a CSS `background-image` with `cover` sizing, so it is cropped and never stretched, plus a dark scrim) behind white text on cards and the vehicle banner.
- **Frontend libraries:** MUI + MUI X (see API), icons from `lucide-react`, `react-grid-layout` for the dashboard's tiles only (`dashboard/DashboardGrid.tsx`, in the dashboard's lazy chunk; `Responsive` over `useContainerWidth({ measureBeforeMount: true })`, so a phone never paints the desktop's grid first, with a desktop fallback width for jsdom and a tab out of sight, and the breakpoint worked out from the width (`breakpointOf`), never from a callback that lags a frame; its stylesheet rewritten in `sx` there, since the app has none, transitions off under reduced motion, the resize corner 44 px and hidden outside edit mode (the library marks such a tile `react-resizable-hide`, whose rule is in the stylesheet the app does not load, #227); it has no keyboard or screen-reader support, so every tile also carries a menu that does what dragging does; while editing a strip (`EditStrip`, `TILE_STRIP` 40 px, #228) lies over each tile's top edge and is the tile's header (#262): the tile's name (a chart's `h2`, the card's own title not drawn meanwhile; the name and the grip are the `.tk-tile-handle`, never a button in either), its `lead` slot (a trend figure's period chip, #260, portaled by `TrendTile`; hidden while empty), the grip (44 px wide at least, so a chip beside it is cut first), the pin, its `actions` slot (a chart's table, edit and delete buttons) and the ⋮ menu; the card under it starts `TILE_INSET` (= `TILE_STRIP`) px down (`tileChrome.ts` `TileStripContext`, the slots handed down by `TileCell` as state, its value memoized so a dragged tile's content does not render on its moves; `ChartCard` with `fill` and `Kpi` draw no header or label row of their own while it is set, `ChartCard` portals its buttons; `useTilePadding`; a dialog or popover opened from a tile wraps its content in `OutsideTile`, so its preview is a card of its own), and a tile being dragged or resized gets a new element on every move (`moving`: the same props, so its content does not render again; the other tiles' elements, the grid's handlers and `MARGIN`/`PADDING` keep their identity), since react-grid-layout 2.3 memoizes its items on their cell and their child element and draws a dragged one at the pointer only when it renders: without it a tile froze under the pointer until it crossed into another cell (#227); the rows are as tall while editing as in view mode (#262, replacing #233's 24 px a row: one row height for every tile cannot add the strip once per tile), so nothing changes size when the dashboard is arranged, and a two-row figure keeps its value under the strip (84 px: 40 + 30 + 12, 2 px to spare); a width is a share of the four desktop columns, so below four columns neither *Wider* nor *Narrower* is offered and a corner resize keeps the stored width), animations: short (about 0.2 s), and only for a change of state, never decoration; `MotionConfig reducedMotion="user"` (main.tsx) keeps only fades under reduced motion. Something that only comes in uses the CSS classes of the theme (`MOTION_CLASSES` in `theme/components.ts`: `tk-appear`, `tk-fade` for a swapped value such as a badge with `key={state}`, `tk-delayed` for a wait indicator, `tk-pulse` for work in progress, `tk-spin`; all off under `prefers-reduced-motion`). Something that leaves or moves uses `motion/react` with the presets in `components/motion.ts` (`MotionTableRow` + `rowMotion` for table rows, `itemMotion` with `layout` for list items; a grid's rows use `useLeavingRows` instead) inside `AnimatePresence initial={false}`. Exception: a home card's attention rows leave at once, because the card moves the focus to its title only once the clicked Done button is gone. Waiting: skeletons (home cards, dashboard, chart cards: a hidden `role="status"` says "Loading…"), `components/Loading.tsx` (spinner + text, `role="status"`) for a page's Suspense, Save buttons `loading={busy}` and `SaveWait` while photos upload, `recognition/ReadingProgress.tsx` in the reading status region ("you can save now", with a bar of the wait that has passed), and a short "Saved." toast after a save. Tests set `MotionGlobalConfig.skipAnimations` (`src/frontend/tankstat-react/tests/support/setup.ts`), so a leaving item is gone at once. Build mobile-first and check desktop too.
