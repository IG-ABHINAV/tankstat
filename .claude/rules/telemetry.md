# Telemetry (OpenTelemetry over OTLP)

- **Opt-in (#214):** traces, metrics and logs through one `UseOtlpExporter()` (it honours a signal's own `OTEL_EXPORTER_OTLP_{TRACES,METRICS,LOGS}_ENDPOINT`; `AddOtlpExporter()` does not, verified), registered by `Api/Telemetry/TelemetryExtensions.AddTelemetry` from `Program.cs` before `Build()`, never for `backup`/`decrypt`/`schema export`, and only when `Application/Telemetry/TelemetryGate` (pure, never throws: telemetry never stops a start) says `On`: `OTEL_EXPORTER_OTLP_ENDPOINT` is the only switch (a signal's own endpoint alone is `SignalEndpointWithoutBase`, off: the other signals would go to the SDK's `localhost:4317`), `OTEL_SDK_DISABLED=true` is `Disabled`, and an endpoint that is not an absolute http(s) URI, a protocol other than exactly `grpc`/`http/protobuf` (the SDK compares as written) or headers that are not `key=value` pairs after URL-decoding (the SDK throws) are `Misconfigured`, base and per-signal keys alike (`OtelSettings`). Without an endpoint nothing is registered (no provider, no HotChocolate listener, no OpenTelemetry logger). `Api/Telemetry/TelemetryReporter` (hosted) says what became of it: Information when on (protocol, signals, service name, never the endpoint or headers), Warning for the problems (named by setting, never by value), the per-signal endpoint alone and `Telemetry:TraceDatabase` set but without effect or not a bool, Debug when simply off; and a Warning at every start while database spans are on.
- **Settings:** the SDK's own `OTEL_*` keys, which it reads from the host's `IConfiguration` (environment, the settings file and the Server settings page alike, verified), plus our `Telemetry:TraceDatabase` (`Application/Telemetry/TelemetryOptions`). The settings catalog's `Telemetry` group (read at start, *Restart needed*) edits `OTEL_EXPORTER_OTLP_ENDPOINT`, `_PROTOCOL` (a choice, words `systemSettings.choices.otlpProtocol`), `_HEADERS` (a secret, the fourth) and `OTEL_SERVICE_NAME` under those very names (exempt from the options-class pin like Logging's framework keys; built-in defaults `grpc` and `tankstat` from `OtelSettings.DefaultOf`), and `Telemetry:TraceDatabase` (pinned to `TelemetryOptions` in `OptionsSections`); `SettingsCatalog.Validate` checks the three shapes as the gate does, `Problems` skips the group (never fatal, like photo reading); the page greys the other four out while the endpoint is empty (`settingsRelevance.ts`, the gate's own rule). The per-signal keys, `OTEL_SDK_DISABLED`, `OTEL_RESOURCE_ATTRIBUTES` and the rest are environment only. `service.name` is set by the app (`OTEL_SERVICE_NAME` or `tankstat`), `service.version` is `HealthReporter.AppVersion`.
- **What is exported keeps the log's promise** (`logging.md`): the instrumentations are ASP.NET Core, HttpClient, HotChocolate (`HotChocolate.Diagnostics`, the version of `HotChocolate.AspNetCore`) and, behind `Telemetry:TraceDatabase`, EF Core (`OpenTelemetry.Instrumentation.EntityFrameworkCore`, a beta, at least 1.20.0-beta.1: no exception message in the span); meters ASP.NET Core's, HttpClient's, `System.Runtime`, `Microsoft.EntityFrameworkCore`; logs with `IncludeScopes` and `IncludeFormattedMessage`. HotChocolate: `RequestDetails = Hash | OperationName` (never `Variables`, `Document` or `Extensions`: the client's JSON), `IncludeDocument`/`IncludeDataLoaderKeys`/`IncludeOperationNameInSpanName` false, `MaxErrorEvents = 0` (an error event carries the message, and keyed messages quote typed values: only `graphql.error.count`), no `ResolveFieldValue` scope (a field span carries the client's alias). `ClientValueRedaction` (a span processor added in `WithTracing`, so before the exporter `UseOtlpExporter` adds; the tests' in-memory exporter, registered later still, gets the redacted spans) removes `user_agent.original` and every `db.query.parameter.*` (which `OTEL_SEMCONV_STABILITY_OPT_IN=database` with `OTEL_DOTNET_EXPERIMENTAL_EFCORE_ENABLE_TRACE_DB_QUERY_PARAMETERS=true` add). The query string's values are redacted by the ASP.NET Core and HttpClient instrumentations by default (`?resetToken=Redacted`); their `OTEL_DOTNET_EXPERIMENTAL_*_DISABLE_URL_QUERY_REDACTION` must never be set. The one-time code's two lines log under their own categories, `OneTimeCode.SetupLine` and `OneTimeCode.RestoreLine` (below `OneTimeCode.LogCategory`), which `AddTelemetry` filters out of the `OpenTelemetryLoggerProvider` by the prefix and by both exact names (no configured rule can be more specific; a tie goes to the later, ours). Never add the database providers' own sources (`Npgsql`, the MySQL connector's): they would trace the commands again past the switch. Metric attributes never carry ids. The accepted edge, documented: the log's, plus `url.path` and `server.address` (the Host header) on request spans, and a provider level of the exporter's own (`Logging:OpenTelemetry:LogLevel:Microsoft.AspNetCore`) below Warning, which the page's floor does not check.
- **Tests:** `TelemetryGateTests` (Application: the gate's table), `SettingsCatalogTests` (the group, shapes, defaults, the fourth secret), `TelemetryTests` (Api integration, a collection of its own with `DisableParallelization = true`, since ActivitySource and logger listeners are the process's: other hosts' spans would land in its exporter): a host with an endpoint nothing listens on (`http://127.0.0.1:1`, refused at once) and in-memory exporters added with `ConfigureOpenTelemetry{Tracer,Logger,Meter}Provider`; the canary flow of #214 (a plate, a name, a note with a quote and a backslash, an odometer refusal, a schedule's title in a refusal, a reset token as a variable and in the query, an alias, `extensions`, a User-Agent) with and without database spans (then with both EF opt-ins set), searched with `CapturedLog.Holds` in every span name, status, tag, event tag and exported log record; the one-time codes (mode None, a waiting setup, and a configured rule for the exact category) never exported; a request as one trace with its log lines; settings that cannot be used. `Program.cs` decides before the host is built, where a `TestApp`'s in-memory settings do not exist yet, so `TestApp` passes every `OTEL_*`/`Telemetry:*` key as a command-line argument (`UseSetting`), an empty one for each the developer's environment sets; `ApiFixture` clears such variables, `AppProcess` and the scripts drop them (`ci-and-tests.md`). Not covered in process: the Kestrel meter (TestServer has none) and the in-process restart, which the smoke tests start for real.
